## 一、原文照录

> 农户贷款作为农业银行服务"三农"战略的核心抓手，业务规模持续扩大，但风险防控压力日益凸显。农户贷款具有单笔金额小、客户分散、抵押物不足、还款能力受自然与市场双重因素影响等特点，传统人工审核难以高效识别潜在风险，导致贷前调查不充分、贷中审批效率低、贷后跟踪不到位等问题频发。为此，本赛题聚焦构建一款集意图识别、风险评估、动态预警于一体的农户贷款风险防控智能体，通过准确理解贷前、贷中、贷后各环节的单一或复合问题，利用相关工具完成信贷调查资料核查、流水分析、风险点审查、贷后管理等任务，输出符合要求的风险识别结果，辅助信贷人员精准、便捷、快速甄别农户贷款风险，在保障信贷资产安全的同时，提升农行服务乡村振兴战略的可持续性与专业性。

## 二、原文讲了什么（结构化提取）

下面全部是**从原文里拆出来的**，没有额外添加。

### 2.1 农户贷款的四个特点 —— 也就是风险从哪来

| 原文说的                 | 意味着什么                       |
| -------------------- | --------------------------- |
| 单笔金额小                | 量大、笔数多 → 人工看不过来，**效率**本身是考点 |
| 客户分散                 | 一户一个样，不可能靠一套话术打天下           |
| **抵押物不足**            | 押品覆盖不够是常态 → 必须专门查抵押物        |
| **还款能力受自然与市场双重因素影响** | 天灾（旱涝病害）和行情（价格涨跌）都能让还款能力变脸  |

> 加粗的两条是**原文点名**的风险来源。出题时必须各有一组题专门考它们。

### 2.2 现状三个痛点 —— 也就是我们要解决的

| 原文说的    | 对应到我们的哪个环节            |
| ------- | --------------------- |
| 贷前调查不充分 | 贷前的材料核查、流水分析、征信审查     |
| 贷中审批效率低 | **贷中**环节（审批、放款、签约、用信） |
| 贷后跟踪不到位 | 贷后监测、预警、处置            |

> **贷前 / 贷中 / 贷后 三环节在原文里是并列点名的。** 出题不能只出贷前和贷后，  
> 贷中必须单独有题——这一条以前容易被忽略。

### 2.3 要做一个什么样的东西

原文给智能体定了三个组成：

| 原文说的     | 含义                  |
| -------- | ------------------- |
| **意图识别** | 用户说一句话，得先听懂他问的是哪档子事 |
| **风险评估** | 判断这笔贷款的风险           |
| **动态预警** | 贷后持续盯着，出苗头就报        |

"集……于一体"——三者都要有，不是三选一。

### 2.4 原文点名的四类任务

> 原文：「利用相关工具完成**信贷调查资料核查、流水分析、风险点审查、贷后管理**等任务」

| 原文任务名    | 我们这边谁干 |
| -------- | ------ |
| 信贷调查资料核查 | 资料核查   |
| 流水分析     | 流水分析   |
| 风险点审查    | 风险规则审查 |
| 贷后管理     | 贷后预警   |

### 2.5 输入与输出

| 原文说的                          | 含义                              |
| ----------------------------- | ------------------------------- |
| 「准确理解贷前、贷中、贷后各环节的**单一或复合**问题」 | 问题有简单有复杂 → 题目必须分**单一**和**复合**两档 |
| 「输出**符合要求**的风险识别结果」           | 有格式要求，不是随便说                     |
| 「辅助信贷人员**精准、便捷、快速**甄别」        | 除了准，还要**快** → 评测要记录花了多少钱、多少时间   |

## 三、从原文直接得出的硬要求

这些不是我的发挥，是把上面的话摊平了说：

1. **三环节都要覆盖**：贷前、贷中、贷后各有题。
2. **四类任务都要覆盖**：资料核查、流水分析、风险点审查、贷后管理各有题组。
3. **单一题和复合题都要有**。
4. **抵押物不足**必须专门出题。
5. **自然因素**和**市场因素**必须各有题，而且**要能分得清**——不能把行情下跌误判成天灾。
6. **效率是考点**：跑分要记录用了多少 token、多少秒。
7. **意图识别要单独考**：出"话里带着别处关键词"的题，看会不会跑错门。

## 四、一个需要注意的地方：征信没被单独点名

原文点名的四类任务是「资料核查 / 流水分析 / 风险点审查 / 贷后管理」——**征信不在其中**。

我们队里把征信单独设了一摊（见 `docs/分工.md`），那是**我们自己加的**。  
分工文档里其实也写了退路：「时间不够就把征信降级成 `sk_rules` 里的一个维度」。

所以出题的取舍是：

- 征信题**要出**（它确实属于"风险点审查"的一部分）
- 但**别把出题精力压在征信上**，优先保证点名的四类任务和三个环节都覆盖到位
- 如果发现征信维度出题太多、而贷中严重不足，那是**优先级搞反了**
