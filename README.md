# abc-fxb-20261008 · 农户贷款风险防控智能体

农业银行「繁星杯」智能体竞赛参赛作品。

---

## 这是个什么东西

做一个 AI 助手，帮信贷员判断**农户贷款有没有风险**。

农户来贷款，信贷员得判断这人靠不靠谱——材料齐不齐？银行流水正常吗？征信有没有问题？贷出去之后会不会还不上？

我们的 AI 就干这个：用户问一句话，它给出风险结论。

## 我们做了个什么结构

想象成**一家银行网点**：

- **主智能体** = 大堂经理。听客户说什么，判断该找哪位专家，最后汇总答复。
- **5 个 skill** = 5 位专家。各管一摊，互不越界。
- **规则库** = 一本风险手册。写着"什么情况算高风险"。

| 专家 | 负责什么 |
|---|---|
| `sk_doc` 资料核查 | 材料齐不齐、对不对得上、有没有过期 |
| `sk_cash` 流水分析 | 收入稳不稳定、有没有异常交易、钱花哪去了 |
| `sk_cred` 征信负债 | 负债率高不高、有没有逾期、借了几家 |
| `sk_rules` 风险规则 | **裁判**——汇总大家的发现，定最终等级 |
| `sk_ew` 贷后预警 | 贷出去之后有没有变坏、要不要催收 |

> **我们写的不是代码**，是给 AI 看的说明书（markdown）+ 几个算数的小脚本（Python）。
> 所以这不是编程比赛，是"怎么把说明书写得又准又省"的比赛。

## 怎么跑起来

```bash
# 打包出最终要交的 6 个 zip
python build/pack.py

# 自测（应该显示"通过：37 项断言"）
python eval/contract_tests.py
```

跑完 `dist/` 文件夹里就是成品。

> **环境**：Windows 下用 `python`，**不要用 `python3`**。中文输出乱码的话，命令前面加 `PYTHONIOENCODING=utf-8`。

---

## 三条必须遵守的规矩

**1. 最终等级只能由 `sk_rules` 来定。**
其他专家只报"我这一摊发现了什么问题"，不能说"所以整体是高风险"。否则同一个客户在不同专家嘴里会得到不同结论。

**2. 规则只写进 `rules/rules.yaml`。**
各专家文件夹里的 `rules.closure.md` 是打包时自动生成的，手改会被覆盖。

**3. 算数交给脚本，AI 只做判断。**
让 AI 算数是三个亏一起吃：算错 + 慢 + 花钱。

## 文件夹

```
contracts/    全队的约定书（改约定先改这里）
rules/        风险手册 + 变量词典
main/         大堂经理的说明书
skills/       5 位专家的说明书（_template 是新建用的模板）
build/        打包工具
eval/         自测工具
docs/         交付说明.md（先读这个）、分工.md（谁干什么）、待裁决问题.md（卡住的地方）
dist/         打包好的成品
```
