# 征信审查要点 · sk_cred 依据库

> 本文件是 `sk_cred` 的**依据库**：`rules/rules.yaml` 里 `basis` 列写的"征信审查要点N"逐条在此。  
> 用途两个：① 解释某条规则的阈值**为什么**是这个数；② 给出计算口径，保证换人实现数值可比。
>
> **阅读纪律**：只在需要解释**具体某条规则**的依据时读对应那一节，不要整体灌入上下文  
> （`max_reads: 2`，整份读进来是设计缺陷）。附表 A/B/C 仅在需要引注原文或核对符号时读。
>
> **维护纪律**：改阈值先改 `rules/rules.yaml`（SSOT），再回来更新本文件对应表格，  
> 最后跑这两条：
>
> ```bash
> python build/check_basis.py    # 校验本文件与规则表是否漂移（阈值/等级/索引）
> python build/pack.py           # 闭包校验 + 打包
> ```
>
> `check_basis.py` 是**本文件的手工同步护栏**：它逐条比对规则的 `cond`、`level`、  
> `basis` 与本文"分档与依据"表是否一致，不一致就 exit 1。  
> **为什么必须有它**：本文与 `rules.yaml` 是手工同步的，漂移是**静默错误**——  
> 规则改了阈值而文档还在解释老阈值，读的人会被误导，且没有任何现有检查能发现  
> （`check_closure.py` 只管规则闭包，看不见本文件正文）。实测：本文曾出现  
> R214 条件未同步、R216 缺分档行两处漂移，都是这个脚本抓出来的。
>
> 只改这里不改 `rules.yaml`，规则行为不会有任何变化。  
> **要点 1–16 的编号被 41 条规则的 `basis` 引用，不允许重排**；新主题只能追加 17+。

## 0. 依据可信度分级（**先读这一节，它决定你敢不敢把某个数说成"监管规定"**）

| 标        | 含义                                                     | 能不能写成"监管要求"      |
| -------- | ------------------------------------------------------ | ---------------- |
| `[法定]`   | 法律／行政法规／部门规章／规范性文件，**已核验文号与条款号**                       | ✅ 可以，须带文号与条款     |
| `[官方口径]` | 人民银行等官方**出版物／知识页**的解释性口径（非条文本身）                        | ⚠️ 只能写"人民银行官方解释" |
| `[司法口径]` | 最高法院裁判规则／司法解释／法答网答问                                    | ✅ 可以，标注法院与文书号    |
| `[机构内控]` | **无全国统一数字依据**，由机构风控自主设定的参数（我们按农行公开产品与同业惯例取值，**需团队复核**） | ❌ **绝对不能**声称监管规定 |
| `[行业惯例]` | 广为人知但**查不到任何监管出处**                                     | ❌ 只能写"行业惯例"      |
| `[未核验]`  | 查不到权威出处，**已如实标注**                                      | ❌ 不得引用           |

**本表存在的意义**：本项目是授信辅助工具。把机构内控参数写成"监管规定"，  
一旦被追问出处就会暴露不实；反之，如实标注不会扣分，**写错会**。

**核验方法**：全部条文经联网检索核验，优先 gov.cn／pbc.gov.cn／nfra.gov.cn／court.gov.cn。  
标 ★ 的 3 份是编写人**亲自逐字比对原文**（非二手转述）：  
**银监发〔2012〕50号**（国务院公报2012年第34号）、  
**金融监管总局令2024年第3号**（国务院公报2024年第12号）、

## 要点1 · 征信报告的获取、授权与时效基线

**关联规则**：无（口径基线，不直接判定）

**口径与依据**：

| 事项           | 结论                                                       | 依据                             | 级别       |
| ------------ | -------------------------------------------------------- | ------------------------------ | -------- |
| 查询须取得授权      | **须"书面同意 + 约定用途"双要件**；例外仅"对已发放个人信贷的贷后风险管理"               | 条例§18；暂行办法§13（例外见§12(四)）       | `[法定]`   |
| 查询用途封闭清单     | 仅 5 种：审核个人贷款、审核贷记卡/准贷记卡、审核个人作为担保人、贷后风险管理、法人贷款时查法定代表人及出资人 | 暂行办法§12                        | `[法定]`   |
| 未经授权查询的后果    | 机构罚 5万–50万（条例）；越权查询/挪用查询结果罚 1万–3万（暂行办法）                  | 条例§40(三)；暂行办法§39(三)(四)         | `[法定]`   |
| 授权查询与审核须分离   | 人工查询要实现查询、审核环节分离，杜绝"一手清"                                 | 人民银行公告〔2024〕第21号（2025-02-05施行） | `[法定]`   |
| 报告有效性        | **无任何监管明文规定"有效期"**（可核验的只有条例§17"每年2次免费获取"）                | —                              | `[机构内控]` |
| 报告缺页/字段大面积空白 | 标 `coverage: partial`，**不得**按"无异常"处理                     | 契约 IF-5.5 降级协议                 | `[机构内控]` |

**为什么单列一条**：本维度所有判断都建立在"报告是合法取得且完整的"这一前提上。  
报告不完整时不报风险 ≠ 没有风险，而是**没有依据**——这两种情况必须在输出里区分开，  
否则会变成"静默漏报"。

**易错点**：

- 把"报告里没有逾期字段"读成"没有逾期"。字段缺失 → `None`（规则跳过 + 标 partial）；  
  字段为 0 → 确实无逾期。
- **不要引用"报告出具后 1 个月/15 天内有效"当作监管要求**——它是银行内部规定。
- 贷后管理查询虽不需客户授权，但须有机构**内部授权制度**（暂行办法§14）。

## 要点2 · 债务收入比（DTI）

**字段**：`dti`　**关联规则**：R201（高）、R202（中）

**口径**：

```
dti = 月均还款额（debt[] 各笔 monthly_pay 之和） / 月均收入（declared_inc）
```

- 分母用**申报月收入** `declared_inc`，不是流水测算收入（跨维度对账归 `sk_rules` 的 X001/X002）。
- 分子**只含在贷月供**，不含本次申请的新增月供。
- `declared_inc` 缺失或 ≤0 → `dti = None`，R201/R202 跳过并标 partial。

**分档与依据**：

| 条件                  | 等级 | 规则           | 依据                       | 级别       |
| ------------------- | -- | ------------ | ------------------------ | -------- |
| `dti > 0.55`        | 高  | R201         | 见下方"阈值从哪来"               | `[机构内控]` |
| `0.5 < dti <= 0.55` | 中  | R202         | 同上                       | `[机构内控]` |
| 环节差异                | —  | `thresholds` | 贷前 0.5 从严／贷中 0.55／贷后 0.6 | `[机构内控]` |

**阈值从哪来（必须如实说明，这是本要点最重要的一段）**：

- **农户贷款没有任何全国性监管数字阈值。** 50号文§19 只要求"农村金融机构应当建立借款人合理的  
  **收入偿债比例控制机制**"；个人贷款办法§10 措辞完全相同；互联网贷款办法§21 要求  
  "结合借款人已有债务情况，审慎评估借款人还款能力"。**三处都只有"机制"，没有数字。**
- **全国唯一可引用的明文比例**是房贷指引§36：住房贷款的"月房产支出与收入比 ≤50%"、  
  "月**所有债务**支出与收入比 ≤55%"。**但它只适用于个人住房贷款，不能外推到农户贷款。**
- 因此 0.55／0.5 这两条线是**机构内控参数**（我们按房贷指引的 50%/55% 量级取整）。  
  评审若追问，答复口径是"依据 50号文§19 的偿债比例控制机制要求，由机构内控设定的阈值"。

**农行公开口径（"以农行为准"的落地结果）**：

| 事项        | 农行公开结论                                                                       | 来源                                  |
| --------- | ---------------------------------------------------------------------------- | ----------------------------------- |
| 计量单位      | 农行采集的是**家庭**口径字段：家庭月收入、**家庭月债务总支出**、保证人月还贷支出、家庭其他月债务支出、**家庭对外担保总额**、家庭供养人口数量 | 农行隐私政策（个人版）贷款业务采集字段                 |
| DTI 审慎线数值 | **未公开**——农行任何公开文本均未给出 DTI 阈值                                                 | 见附表E第 6 节                           |
| 还款方式      | 合同设为**三选一**：①利随本清到期一次性；②按（月/季/半年/年）结息、到期还本；③等额本息／等本递减分期                      | 农行借款合同（网络版）**ABC（2024）6001-1** §4.2 |
| 逾期／挪用罚息   | 逾期罚息＝**执行利率上浮 50%**；未按约定用途使用＝**上浮 100%**                                     | 同上 §9.2／§9.3                        |

→ **三条重要修正**：

1. **DTI 应以"家庭"为单位计量**（与农行公开采集口径一致）。本章 `dti` 目前用 `declared_inc`  
   （个人申报月收入）作分母，**存在口径缺口**：建议任务3 新增 `family_income` 与  
   `family_debt_pay`（后者须含家庭对外担保对应的或有支出）。
2. **不能默认等额本息**。对"②结息到期还本"须单独计算**到期一次性还本**的集中偿付压力；  
   对"①利随本清"须计算到期全额压力。否则 dti 会系统性低估还款压力。
3. **农行没有"必须按月／按季分期还款"的统一硬性要求**——合同是借贷双方**勾选三选一**。  
   因此规则不得假定"农户贷款都是分期还款"。

**为什么用"月供"而不是"贷款余额"**：余额不反映还款压力。同样 10 万元，  
1 年期与 5 年期的月供差 5 倍。

**规则编码口径**：R201/R202 按**贷中（审批）**&#x53E3;径 0.55 编码，与 `dict.yaml` 的  
`thresholds.dti` 贷中列一致。贷前从严、贷后放宽由 `sk_rules` 结合 `factors` 行回传的  
`dti` 与 `dti_threshold` 决定——**本维度不改写规则**，避免同一现象在不同环节给出两套矛盾等级。

**易错点**：忘记算共同借款人负债（要点14）和对外担保（要点13）→ dti 系统性偏低；  
但这两项**不并入 dti**，由各自要点独立定级（防等级冲突）。

## 要点3 · 信用历史长度与"白户"处理

**字段**：`credit_hist_len`　**关联规则**：R212（中）、R232（低）

**分档与依据**：

| 条件          | 等级 | 规则   | 依据                | 级别       |
| ----------- | -- | ---- | ----------------- | -------- |
| `< 12` 月    | 中  | R212 | 不足 12 个月还款表现，预测力弱 | `[机构内控]` |
| `12 ~ 24` 月 | 低  | R232 | 略短，提示性            | `[机构内控]` |

**为什么最高只到"中"——这是本要点的核心，也是合规红线**：

"白户"（无征信记录）在农户中占比极高。把它判"高"等于对整类客户系统性拒贷，  
而监管方向恰恰相反：

| 依据             | 原文要点                                                  | 级别     |
| -------------- | ----------------------------------------------------- | ------ |
| 50号文§13(六)     | 贷款条件只要求"借款人**无重大**信用不良记录"——**是"无不良"，不是"必须有记录"**       | `[法定]` |
| 50号文§23(三)     | 贷前调查须了解"借款人（户）**信用状况**"                               | `[法定]` |
| 50号文§24        | 须深入了解"人品、信用等**软信息**"，借助**村委会、德高望重村民、经营共同体带头人**等社会力量   | `[法定]` |
| 银保监办发〔2022〕35号 | "**加大首贷户拓展力度，更多为此前未从银行获得贷款的客户提供金融服务**，积极填补农村金融服务市场空白" | `[法定]` |
| 三农通知           | "**拓展涉农'首贷户'**"                                       | `[法定]` |
| 国发〔2023〕15号    | "**持续增加首贷户**"                                         | `[法定]` |

> ⚠️ **不要引用"监管明确要求不得设置歧视性准入门槛"**——经精确检索，  
> **该措辞不存在于任何涉农信贷/普惠金融文件**（命中的全是招投标、事业单位招聘类文件）。  
> 上面 6 条才是可核验的替代论证链。级别：`[未核验]`（原表述）。

**"白户"规模的可用数字**（引用时须注明口径与年份）：

| 数字                      | 口径与时间              | 来源可靠性                              |
| ----------------------- | ------------------ | ---------------------------------- |
| 收录自然人 **11.6 亿**        | 2023年末，金融信用信息基础数据库 | 人民银行《中国普惠金融指标分析报告》                 |
| 收录 **8.1 亿**自然人**信贷信息** | 2025年11月末          | 人民银行副行长邹澜公开披露                      |
| "约 **4 亿**人无任何信贷信息记录"   | 2024年11月           | ⚠️ **上海证券报转述"记者获悉"，非央行正式统计**，引用须注明 |

**易错点**：`credit_hist_len = 0`（确实无信贷记录）与字段缺失（`None`）不同：  
前者走 R212 提示，后者只能标 partial。  
**对策**：判中/低 + 要求替代数据（村委证明、水电缴费、合作社结算记录、土地承包合同、  
农业保险保单），而不是拒贷。

## 要点4 · 逾期画像

**字段**：`overdue_cur` / `overdue_24m` / `overdue_max_days`　  
**关联规则**：R205 R206 R207 R214 R215

**口径**：

- `overdue_cur`：**当前仍未结清**的逾期账户笔数。
- `overdue_24m`：最近 24 个月逾期**次数合计**。
- `overdue_max_days`：单次**最长**逾期天数（由官方符号的期数换算，一期按 30 天）。

**分档与依据**：

| 条件                                               | 等级 | 规则   | 依据                                                                   | 级别       |
| ------------------------------------------------ | -- | ---- | -------------------------------------------------------------------- | -------- |
| `1 ≤ overdue_max_days < 30` 且 `overdue_cur == 0` | 低  | R214 | 官方符号 `1`＝"逾期1－30天"；`overdue_cur==0` 限定它只管**历史已结清**的短期逾期（避免与 R215 冲突） | `[官方口径]` |
| `30 ≤ overdue_max_days < 90`                     | 中  | R206 | 官方符号 `2`/`3`＝逾期31－90天，须核因                                            | `[官方口径]` |
| `overdue_max_days ≥ 90`                          | 高  | R205 | **分类办法§11(一)：逾期超过90天应至少归为次级类（不良）**                                   | `[法定]`   |
| `overdue_24m ≥ 3`                                | 中  | R207 | 频次信号，无监管阈值                                                           | `[机构内控]` |
| `overdue_cur ≥ 1`                                | 高  | R215 | 当前未结清＝当下偿付意愿的直接证据                                                    | `[机构内控]` |

**30/90 天分界从哪来**：官方还款状态符号以 **30 天为一期**（`1`=1–30天 … `7`=180天以上），  
给出 30/60/90 的粒度；分类办法给出 **90／270／360 天的法定下限**（§11(一) 90天次级、  
§12(一) 270天可疑、§13(一) 360天损失）。两者叠加，本维度只用 30/90 两档（其余档位由  
`sk_rules` 的定级合成处理）。

**R214 与 R215 的冲突已修正**：两条原本会被**同一个事实**同时命中（当前有一笔 10 天逾期  
→ 低 + 高），同一事实出现两个等级。现已给 R214 加 `&& overdue_cur == 0`，明确它只管  
"**历史已结清**的短期逾期"。

> 副作用：`overdue_cur` 缺失时 R214 会被跳过（标 `partial`）——符合"缺数据不猜"原则，  
> 但意味着**数据源必须提供 `overdue_cur`**，否则会丢掉"历史短期逾期"这条低风险提示。

**易错点**：

- **`B`（呆账）符号未获官方出处**——人民银行公开的《还款状态说明》里**没有 `B`**。  
  呆账应取自征信报告的**账户状态**字段，不能从还款状态符号推断。见要点5。
- **"连三累六"没有任何监管依据**（检索 gov.cn／pbc.gov.cn／nfra.gov.cn 均无此表述），  
  它是行业惯例。**不要标成监管规定**；需要法定口径时改用分类办法的 90/270/360 天。
- 分类办法§10(一) 明确"**操作性或技术性原因导致的短期逾期除外（7天内）**"——  
  7 天内的技术性逾期不应计入风险。
- 逾期 10 元与逾期 10 万元计次相同 → 脚本无法判金额轻重，须靠 L2 证据行交人工核实。

## 要点5 · 呆账、代偿与核销

**字段**：`bad_debt_flag`　**关联规则**：R216（高）

**口径**：征信出现呆账、核销、或 `D`（担保人代还）后仍有未结清代偿 → `bad_debt_flag = 1`。

| 事项                     | 结论                                                                                                   | 依据                                                     | 级别       |
| ---------------------- | ---------------------------------------------------------------------------------------------------- | ------------------------------------------------------ | -------- |
| "不良信息"的法定范围            | 含未按合同履行义务的信息、行政处罚信息、法院判决/强制执行信息                                                                      | 条例§44(三)                                               | `[法定]`   |
| 不良信息保存期限               | 自不良行为或事件**终止之日起 5 年**，超过应删除                                                                          | 条例§16；征信办法§20                                          | `[法定]`   |
| 一次性信用修复（**新规，必须前置过滤**） | 2020-01-01 至 2025-12-31 期间、**单笔金额 ≤1 万元**的个人逾期，于 **2026-03-31（含）前足额偿还**的，金融信用信息基础数据库**不予展示**（无需个人申请） | 人民银行《关于实施一次性信用修复政策有关安排的通知》，2025-12-22发布（**原文未标注发文字号**） | `[法定]`   |
| 官方还款状态符号               | `/ * N 1–7 D Z C G #`（见附表B），**无 `B`**                                                                | 人民银行《百姓征信知识问答》还款状态说明                                   | `[官方口径]` |

**分档与依据**：

| 条件                   | 等级 | 规则   | 依据                                                          |
| -------------------- | -- | ---- | ----------------------------------------------------------- |
| `bad_debt_flag == 1` | 高  | R216 | 条例§16（不良信息 5 年保存期）／§44(三)（不良信息法定定义）。**须先过一次性信用修复豁免过滤**（见上表） |

**为什么"呆账"仍是高风险**：放贷机构已认定这笔钱收不回来并计提损失，是征信里最严重的记录，  
恢复路径是"结清 + 5 年"。

**⚠️ 必须叠加一次性信用修复过滤（否则会误判）**：报"呆账/逾期一票否决"前须先过三道前置条件  
——金额 ≤1 万元、逾期发生于 2020-01-01～2025-12-31、已于 2026-03-31 前足额偿还。  
三者同时满足的逾期**本就不应展示**，若模型仍据旧报告数据报出否决，属误报。

**易错点**：只看 `overdue_cur` 会漏掉呆账（呆账账户可能已不在"当前逾期"口径内）→  
必须**独立取账户状态字段**，不能从逾期字段推导。

## 要点6 · 失信被执行与涉诉

**字段**：`dishonest_flag` / `lawsuit_flag`　**关联规则**：R217（高）、R218（中）

**⚠️ 本节是本次核验中修正幅度最大的一节。** 原稿写的"失信被执行人属**法定禁入**情形"  
**不成立**——现行规定既设纳入期限，又设"不得纳入"与"应当删除"情形。

**失信规定的关键条款**（法释〔2017〕7号修正，★ 已逐字核验）：

| 条     | 内容（要点）                                                                                       | 对规则的含义                     |
| ----- | -------------------------------------------------------------------------------------------- | -------------------------- |
| §1    | 六种纳入情形；第(一)项限定语是"**有履行能力而拒不履行**"                                                             | 不能简化为"有失信记录即高风险"           |
| §2    | 纳入期限 **2 年**；情节严重或多项失信可延长 **1–3 年**；积极履行可提前删除                                                | **必须做时点有效性校验**，不是永久标记      |
| §3    | **4 种不得纳入**：①**提供了充分有效担保的**；②查封扣押冻结财产足以清偿；③履行顺序在后不应强制执行；④其他不属于"有履行能力而拒不履行"                   | **① 与担保规则直接互斥**，需反向判断      |
| §4    | 被执行人**为未成年人**的，不得纳入                                                                          | 须做主体资格校验                   |
| §8(2) | 法院应将失信名单信息**向征信机构通报**，由征信机构记录                                                                | 这是"征信数据可依法采信失信名单"的**授权依据** |
| §10   | **7 种应当在 3 个工作日内删除**的情形（已履行、执行和解履行完毕、申请执行人书面申请、终本后两次查无财产、中止执行、不予执行、终结执行）；**期限届满后 3 个工作日内删除** | **必须支持"已删除/已终本"的正向豁免**     |


**分档与依据**：

| 条件                                      | 等级 | 规则   | 依据                                      | 级别       |
| --------------------------------------- | -- | ---- | --------------------------------------- | -------- |
| `dishonest_flag == 1`（**经时点与豁免校验后仍有效**） | 高  | R217 | 失信规定 §1/§2/§3/§4/§10                    | `[司法口径]` |
| `lawsuit_flag == 1`                     | 中  | R218 | 50号文§23(三)"借款人（户）信用状况"（**仅作监管挂靠，等级自定**） | `[机构内控]` |

**为什么涉诉只给"中"**：同级法院诉讼可能源于同名同姓、担保连带、劳动争议，与偿付意愿无必然关系，  
且标的可能极小。直接判高会造成大量误报。**须按身份证号比对，不能按姓名匹配。**

**R217 的表述已修正**：原 `advice` 为"一票否决并拒贷"，与规范文本冲突（该规定设 2 年纳入期限、  
4 种不得纳入、7 种应删除，**不存在"法定禁入"**）。现改为"**核实失信状态与期限**"，  
即把判断交回人工，规则只负责提示。

> **仍待补的能力**：规则引擎目前拿不到"失信状态的时点有效性"。要做到规定 §2／§3／§10 要求的  
> 期限与豁免校验，需要一个**由数据源判定过的**布尔字段（如 `dishonest_valid`＝当前有效），  
> 而不是让规则去算日期。此项列入任务3（需新短码，走 P1 评审）。

**易错点**：失信名单是**动态**的。报告上的记录可能已被删除（§10），  
或已过纳入期限（§2）。规则必须消费"当前有效"状态，而非历史快照。

## 要点7 · 贷记卡：使用率、账户数、准贷记卡透支

**字段**：`card_util` / `card_cnt` / `semi_card_overdraft`　  
**关联规则**：R210 R219 R233 R239

**口径**：

- `card_util` = 已用额度 / 总授信额度（**所有**贷记卡合并）。总授信额度缺失 → `None`，  
  **绝不填 0**（否则 R210/R233 静默失效）。
- `semi_card_overdraft` = 准贷记卡透支超过 60 天未还。

**分档与依据**：

| 条件                         | 等级 | 规则   | 依据                                             | 级别       |
| -------------------------- | -- | ---- | ---------------------------------------------- | -------- |
| `0.7 < card_util ≤ 0.85`   | 低  | R233 | 使用率偏高，提示流动性                                    | `[机构内控]` |
| `card_util > 0.85`         | 中  | R210 | 长期依赖授信周转                                       | `[机构内控]` |
| `card_cnt ≥ 6`             | 中  | R219 | 账户多＝潜在负债扩张空间大                                  | `[机构内控]` |
| `semi_card_overdraft == 1` | 高  | R239 | **官方符号**：准贷记卡 `1`–`7`＝"透支1–30天…180天以上"，透支超期即逾期 | `[官方口径]` |

**信用卡侧的法定"合并授信"要求**（可作为征信审查的监管挂靠点）：

| 依据        | 内容                                                                       | 级别     |
| --------- | ------------------------------------------------------------------------ | ------ |
| 信用卡办法§50  | 发卡银行应对持卡人名下多个信用卡账户授信额度等**合并管理，设定总授信额度上限**（**限本行，非跨行**）                   | `[法定]` |
| 信用卡通知(十一) | "对经查**在不同机构存在多项债务记录**的客户，应当**从严审核**，严格防范多头借贷风险"                          | `[法定]` |
| 信用卡通知(十二) | **唯一明确要求"跨机构额度扣减"**&#x7684;条文（在授信审批/提额时须扣减已获其他机构信用卡授信额度）——**适用范围是信用卡业务** | `[法定]` |

**为什么账户数只给"中"**：账户多而使用率低说明只是授信储备充足，不是当前压力。  
账户数的意义在于"**可扩张的隐性负债空间**"，不能与"高使用率"同等对待。

**易错点**：`card_util` 与 `dti` 会同时失真——高使用率的卡债月供若未进 `debt[]`，  
dti 会偏低。两者要一起看，但**分别定级、不叠加**。

| 条件                            | 等级 | 规则   | 依据                                       |
| ----------------------------- | -- | ---- | ---------------------------------------- |
| `five_level_bad == 1`（关注类及以下） | 高  | R236 | 分类办法§6/§10/§11；50号文§45"严格按照风险分类的规定…准确分类" |
| `1 ≤ extension_cnt ≤ 2`       | 中  | R237 | 偶发展期需核实原因；50号文§43 允许因灾害/价格波动合理展期         |
| `extension_cnt ≥ 3`           | 高  | R238 | **50号文§43"不得再次展期" + 分类办法§22"再次重组至少次级类"** |

**"频繁展期=高风险"是本项目依据最硬的一条**：50号文§43 直接**禁止**二次展期，

可直接锚定为不良级风险。

**口径澄清（任务3 待办）**：`extension_cnt` 目前是**历史累计展期次数**（跨所有贷款）。  
而 §43 的"不得再次展期"指的是**同一笔贷款**不得二次展期。若数据可区分，  
应改为"同一笔贷款展期次数≥2"才是真正的违规信号。字段口径待细化。

**易错点**：展期在征信上可能显示为**正常还款**，不体现在逾期字段里。  
只看逾期会让"靠展期续命"的客户看起来干干净净——这正是最危险的一类。

## 要点9 · 多头借贷与新增授信机构

**字段**：`multi_lend` / `new_org_6m`　**关联规则**：R203 R204 R240

**口径**：

- `multi_lend` = **在贷机构家数**，按机构名去重（同一家银行的不同支行算 **1 家**）。
- `new_org_6m` = 近 6 个月**新发生授信**的机构家数（增量）。

**关键结论：不存在"不得向已在 X 家机构在贷的客户新增授信"的全国性硬性规定。**  
监管只有原则性要求 + 合并额度管理要求，家数阈值属机构自主。

| 依据                         | 内容                                                                                     | 级别                         |
| -------------------------- | -------------------------------------------------------------------------------------- | -------------------------- |
| 信用卡通知(十一)                  | "对经查在不同机构存在多项债务记录的客户，应当**从严审核**，严格防范多头借贷风险"（用词是"从严审核"，**不是"不得授信"**）                    | `[法定]`                     |
| 三农通知(十五)                   | "**防止并纠正对涉农优质客户过度授信、'内卷式'竞争等现象**"——**涉农领域"过度授信"的直接依据**                                 | `[法定]`                     |
| 互联网贷款办法§21                 | "加强统一授信管理，**运用风险数据，结合借款人已有债务情况，审慎评估借款人还款能力**"                                          | `[法定]`                     |
| 50号文§16                    | 授信额度应综合"生产经营状况、**偿债能力**、贷款真实需求、信用状况、担保方式…"确定                                           | `[法定]`                     |
| **农行借款合同 §9.5(4)／§8.6(4)** | 把"在贷款人、农业银行其他分支机构或**其他金融机构**发生的其他债务，**出现逾期或存在不良信用记录**"列为贷款人可**提前收贷、下调风险分类、冻结／调减额度**的事由 | `[机构内控]`（农行合同原文，**非监管规定**） |

**口径修正（重要）**：农行公开合同把"**跨机构逾期／不良**"做成**触发条件**，而不是"家数上限"。  
所以更贴合农行口径的做法是：

- 触发规则优先用"**其他机构债务出现逾期或不良**"（有合同原文依据，可解释性强）；
- 家数（`multi_lend`）只作**弱信号**，且必须标 `[机构内控]`，**不得写成"农行规定"**。

**农行公开的产品额度档位**（可作为"额度与经营规模匹配"的参考锚点，均来自官网产品页）：

| 产品         | 额度                | 期限   | 担保方式                                        |
| ---------- | ----------------- | ---- | ------------------------------------------- |
| 富民贷        | 3000 元 – **20 万** | ≤5 年 | **信用**（执行 1 年期 LPR）；160 个重点帮扶县；**以家庭为单位发放** |
| 农户小额贷款     | 3000 元 – **30 万** | ≤8 年 | 官网未披露                                       |
| 惠农e贷       | 3000 元 – **50 万** | ≤8 年 | 可纯信用，也可抵押、保证                                |

> 另有农行**地方实践**的可引用量化口径（金融时报报道农行迭部县支行）：  
> "收入测算，以农户近一年经营总收入为基准，**按 30% 比例核定授信额度**"、  
> "客户自有资金投入占比**不低于 30%**"。**注意：这是地方分支行做法报道，不是总行统一规定**，  
> 引用时必须注明来源。级别：`[机构内控]`。

**分档与依据**：

| 条件                   | 等级 | 规则   | 依据                              | 级别       |
| -------------------- | -- | ---- | ------------------------------- | -------- |
| `2 ≤ multi_lend ≤ 3` | 中  | R204 | 适度多头，关注新增融资                     | `[机构内控]` |
| `multi_lend ≥ 4`     | 高  | R203 | 4 家以上常见于以贷养贷；挂靠三农通知(十五)"防止过度授信" | `[机构内控]` |
| `new_org_6m ≥ 3`     | 中  | R240 | 短期内在多家机构新开户＝正在到处找钱              | `[机构内控]` |

**为什么把"存量多家"与"增量多家"分开**：存量多头可能是多年正常经营扩张的结果；  
短期增量多头才是资金链紧张的信号。为避免与 R203 对同一现象给出两个等级，  
`new_org_6m` 一律只给"中"。

**易错点**：按"贷款笔数"而非"机构家数"计数，会把同一家银行的 3 笔算成 3 家 → 虚高误报。  
脚本按 `debt[].org` 去重；**若任一笔明细缺机构名，`multi_lend` 直接给 `None` 并标 partial**，  
而不是按"能数出来的几家"计数——否则 8 笔全缺机构名时会得出"0 家机构"，  
把多头风险**静默抹掉**（这是本项目最需要防的失败模式）。

**同样不能"少加一点"**：`debt[]` 任一明细缺 `balance` 时，`debt_balance` 与 `total_debt`  
都必须是 `None`——**部分和不等于总额**，给一个偏低的数会直接让 `X003`（总负债超年收入）漏报。

**口径**：近 3 个月内**新发放**贷款的笔数与合同金额合计（不含本笔申请）。

**分档与依据**：

| 条件                                    | 等级 | 规则   | 依据                | 级别       |
| ------------------------------------- | -- | ---- | ----------------- | -------- |

## 要点12 · 负债结构（信用类占比、短期占比）

**字段**：`unsecured_ratio` / `short_term_ratio`　**关联规则**：R224 R225 R226

**口径**：

```
unsecured_ratio  = (信用 + 保证类) 在贷余额 / 在贷总余额
short_term_ratio = 剩余期限 <= 12 月的在贷余额 / 在贷总余额
```

- **"保证"计入无抵押**：第三方保证的可靠性弱于硬抵押（保证人可能同时是担保圈成员，见要点13）；  
  且民法典§686 推定一般保证，风险敞口更低（见要点13）。
- 类型判定**先看"抵押/质押"，再看"信用/保证"**——否则"抵押担保"会被"担保"二字误判成无抵押。
- 余额明细不全 → 比率 `None`（分母不完整会让比率系统性偏低 → 漏报），标 partial。
- `remain_months` 缺失 → `short_term_ratio = None`（不可按"全部短期/全部长期"猜）。

**分档与依据**：

| 条件                            | 等级 | 规则   | 依据                | 级别       |
| ----------------------------- | -- | ---- | ----------------- | -------- |
| `0.7 < unsecured_ratio ≤ 0.9` | 中  | R225 | 无抵押敞口为主           | `[机构内控]` |
| `unsecured_ratio > 0.9`       | 高  | R224 | 几乎没有抵押覆盖，违约后无追偿来源 | `[机构内控]` |
| `short_term_ratio > 0.7`      | 中  | R226 | 依赖每年续贷，银行一收紧即断链   | `[机构内控]` |

**为什么结构比总量更重要**：同样 20 万负债，"全额抵押、5 年期"与"全额信用、1 年期"  
的风险敞口完全不同，处置方案也不同。

**可挂靠的监管依据**：50号文§23(二) 要求贷前调查"**借款户收入支出与资产、负债等情况**"；  
§15 明确农户贷款按信用形式分"信用贷款、保证贷款、抵押贷款、质押贷款，以及组合担保方式贷款"  
——**本要点的类型划分与监管的分类口径一致**。级别：`[法定]`（分类口径部分）。

**易错点**：`unsecured_ratio` 在"确实无任何在贷余额"时是 `None`（比率无定义），  
**不是 0**。这不算数据缺失，不标 partial。

建议新增 `guarantee_secured_cnt`（连带责任保证笔数）与 `guarantee_expired_cnt`（保证期间已届满笔数），  
否则本要点的"风险分层"只能停留在文档层面。

**易错点**：**不要把 `guarantee_bal` 并入 `dti`**。强行并入会让 dti 命中 R201/R202，  
与 R211/R227 形成"同一现象两个等级"的冲突。本维度独立定级。

**`total_debt` 的口径（已按"超集"落地）**：契约 IF-4 的 `upstream` 声明 `total_debt <- sk_cred`，  
而 `sk_cred/skill.md` 的边界原写"不算 `total_debt`"——**两处不一致**。为不阻塞下游，  
`cred.py` 现按**超集**回传三个数：`debt_balance`（在贷余额）、`guarantee_bal`（对外担保）、  
**`total_debt = debt_balance + guarantee_bal`**。这样无论 P2 裁决为"谁算"，下游都不缺数据。  
**判定仍归 `sk_rules` 的 `X003`**（"总负债超年收入"），本维度只提供数值。  
任一加数不可得时 `total_debt = None`（绝不用已知的那一半顶替，否则会低估总负债）。

## 要点14 · 共同借款人负债

**字段**：`co_borrower_debt` / `co_borrower_dishonest`　**关联规则**：R229 R230 R235

**口径**：共同借款人（配偶、合伙人、同一经营主体的共借人）名下限有负债**余额**合计。

**法律与监管依据**：

| 依据               | 原文要点                                                                                | 级别     |
| ---------------- | ----------------------------------------------------------------------------------- | ------ |
| **50号文§13(一)** ★ | "农户贷款**以户为单位申请发放，并明确一名家庭成员为借款人**"——"以户为单位"是合并计算的**监管设计原点**                          | `[法定]` |
| **民法典§56**       | "**农村承包经营户的债务，以从事农村土地承包经营的农户财产承担；事实上由农户部分成员经营的，以该部分成员的财产承担**"——**比 §1064 更直接适用于农户** | `[法定]` |
| 民法典§1064         | 夫妻共同签名或事后追认的债务、为家庭日常生活需要所负债务属**夫妻共同债务**；超出家庭日常生活需要的，债权人能证明用于共同生活/共同生产经营的除外          | `[法定]` |
| 50号文§16 ★        | 授信额度应综合"偿债能力、贷款真实需求…"确定                                                             | `[法定]` |
| 50号文§19 ★        | 建立"**收入偿债比例控制机制**"                                                                  | `[法定]` |

**分档与依据**：

| 条件                                  | 等级 | 规则   | 依据             | 级别       |
| ----------------------------------- | -- | ---- | -------------- | -------- |
| `6*inc < co_borrower_debt ≤ 12*inc` | 中  | R230 | 家庭合计杠杆偏高       | `[机构内控]` |
| `co_borrower_debt > 12*inc`         | 高  | R229 | 家庭合计杠杆过重       | `[机构内控]` |
| `co_borrower_dishonest == 1`        | 高  | R235 | 连带责任下主借人实际独自承担 | `[司法口径]` |

**为什么必须单列**：共同借款是**连带责任**——共同借款人还不上，主借人必须还。  
只算主借人自己的负债，会让家庭真实杠杆系统性偏低，这是农户贷款最容易漏的一类。  
50号文§13(一)"以户为单位"正是针对这一点的制度设计。

**为什么不并入 `dti`**：共同借款人可能有自己的收入，直接并进主借人的 `dti` 会  
同时高估分子、低估分母，且会与 R201/R202 冲突。故独立定级，由 `sk_rules` 汇总。

**易错点**：农户"个人"与"家庭经营"普遍不分账（见要点16），  
"谁是共同借款人"要以**征信和合同**为准，不能凭流水往来推断。

## 要点15 · 放款前集中结清与以贷养贷

**字段**：`settled_recent` / `settled_amt_recent` / `refinance_flag`  
**关联规则**：R213 R231 R241

**口径**：

- `settled_recent`：本次申请前 3 个月内**集中结清**大额贷款（行为标记）。
- `settled_amt_recent`：本次申请前 3 个月内集中结清的金额合计。
- `refinance_flag`：本次**申报用途**即为偿还他行贷款／置换旧债。

**法律依据（本节依据强度很高）**：

| 依据             | 内容                                                                                                                | 对本项目的含义                                                  | 级别            |
| -------------- | ----------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------- | ------------- |
| **担保解释§16**    | 主合同当事人协议**以新贷偿还旧贷**：请求**旧贷**担保人承担责任的，法院**不予支持**；新贷与旧贷担保人**不同**或旧贷无担保新贷有担保的，请求**新贷**担保人承担责任**亦不予支持**（除债权人证明新担保人知情） | **"担保效力断链"**——借新还旧一旦伴随担保人更换，新担保人原则上不担责。这是**法律风险**，不是道德判断 | `[法定]`        |
| **50号文§43** ★  | 展期须因"因**自然灾害、农产品价格波动**等客观原因"；**已展期贷款不得再次展期**；展期贷款**最高列入关注类**                                                      | 反复展期＝违规信号                                                | `[法定]`        |
| **50号文§44** ★  | 协议重组须满足"利息还清、本金部分偿还、**原有担保措施不弱化**"                                                                                | 重组不得弱化担保，是"担保效力断链"的监管视角                                  | `[法定]`        |
| 分类办法§10(三)     | 通过**借新还旧**或其他债务融资方式偿还的，**至少归为关注类**                                                                                | 借新还旧的资产分类下限                                              | `[法定]`        |
| 分类办法§22        | 观察期内**再次重组** → **至少次级类**                                                                                          | 反复借新还旧可锚定为不良                                             | `[法定]`        |
| 民借贷规定§13(一)(三) | 民间借贷合同无效情形：**套取金融机构贷款转贷**的；未依法取得放贷资格以营利为目的向**社会不特定对象**提供借款的（职业放贷人）                                                | 识别"农户从银行低息贷款后转贷牟利"与"向非正规渠道高息借款"                          | `[法定]`（文号未核验） |
| 民借贷规定§27       | 利息计入后期本金（利滚利）的认定规则                                                                                                | "以贷养贷"在民间借贷场景的直接规范                                       | `[法定]`（文号未核验） |
| 民借贷规定§1(2)     | 金融机构发放贷款引发的纠纷**不适用本规定**                                                                                           | 本要点适用于农户与**非正规渠道**的借贷                                    | `[法定]`        |

**分档与依据**：

| 条件                                                            | 等级 | 规则   | 依据                                          | 级别         |
| ------------------------------------------------------------- | -- | ---- | ------------------------------------------- | ---------- |
| `settled_recent == 1`                                         | 中  | R213 | 有集中结清行为，需核实资金来源                             | `[机构内控]`   |
| `settled_amt_recent > new_loan_amt_3m && new_loan_amt_3m > 0` | 高  | R231 | **结清额大于新增额＝借新还旧特征**；挂靠担保解释§16 + 50号文§43/§44 | `[法定]`（挂靠） |
| `refinance_flag == 1`                                         | 高  | R241 | 分类办法§10(三) 借新还旧至少关注类；50号文§14 用途须合法          | `[法定]`（挂靠） |

**为什么这是最危险的一类**：借新还旧**掩盖真实偿付能力**，是债务"庞氏化"的早期特征——  
一旦新增融资中断，立刻违约。而它在征信上往往表现为"还款记录良好"，恰好把风险藏起来。

**R213 与 R231 为什么不算"同一现象两个等级"**：R213 的条件是"**有**集中结清行为"（中），  
R231 的条件是"**结清额大于新增额**"（高）——后者是前者内部的、性质更严重的子集（借新还旧），  
两者条件不同、严重度递进。与"对同一区间给出两个等级"是两件事。

**易错点**：正常的**产品置换**（用低息贷款置换高息贷款、降低成本）也会命中 R231。  
所以 `advice` 是"核实结清资金来源"而不是直接拒贷。
