# 流水分析要点 · sk_cash 依据库

> 本文件是 `sk_cash` 的**依据库**：`rules/rules.yaml` 里 `basis` 列写的"流水分析要点N"逐条在此。  
> 用途两个：① 解释某条规则的阈值**为什么**是这个数；② 给出计算口径，保证换人实现数值可比。
>
> **阅读纪律**：只在需要解释**具体某条规则**的依据时读对应那一节，不要整体灌入上下文  
> （`max_reads: 2`，整份读进来是设计缺陷）。附表仅在需要引注原文或核对索引时读。
>
> **维护纪律**：改阈值先改 `rules/rules.yaml`（SSOT），再回来更新本文件对应表格，  
> 最后跑 `python build/pack.py`。本文件正文与规则表是**手工同步**的，漂移是静默错误。
>
> 只改这里不改 `rules.yaml`，规则行为不会有任何变化。  
> **要点 1–11 的编号被 12 条规则的 `basis` 引用，不允许重排**；新主题只能追加 12+。

## 0. 依据可信度分级（**先读这一节，它决定你敢不敢把某个数说成"监管规定"**）

| 标        | 含义                                                     | 能不能写成"监管要求"      |
| -------- | ------------------------------------------------------ | ---------------- |
| `[法定]`   | 法律／行政法规／部门规章／规范性文件，**已核验文号与条款号**                       | ✅ 可以，须带文号与条款     |
| `[官方口径]` | 人民银行等官方**出版物／知识页**的解释性口径（非条文本身）                        | ⚠️ 只能写"官方解释"      |
| `[司法口径]` | 最高法院裁判规则／司法解释／法答网答问                                    | ✅ 可以，标注法院与文书号    |
| `[机构内控]` | **无全国统一数字依据**，由机构风控自主设定的参数（按农行公开产品与同业惯例取值，**需团队复核**） | ❌ **绝对不能**声称监管规定 |
| `[行业惯例]` | 广为人知但**查不到任何监管出处**                                     | ❌ 只能写"行业惯例"      |
| `[未核验]`  | 查不到权威出处，**已如实标注**                                      | ❌ 不得引用           |

**本表存在的意义**：本项目是授信辅助工具。把机构内控参数写成"监管规定"，一旦被追问出处就会暴露不实。

**关键结论（先记死）**：**流水分析的所有数值阈值，没有任何全国性监管数字。**  
农户贷款监管（50号文）只给"机制"（"合理确定期限""建立收入偿债比例控制机制"），不给"变异系数 ≤ X""断档 ≤ Y"。  
所以本文件 11 个要点里，**凡是有数字的分档线，一律标 `[机构内控]`**；能挂靠监管的只有"机制要求"本身（用途合法、严禁现金发放、期限匹配生产周期），且挂靠时必须写清"这是机制要求，不是数字阈值"。

**核验方法**：50号文（银监发〔2012〕50号）相关条款已由邱家杰在 `征信审查要点.md` 中标注 ★ **逐字核验**（国务院公报2012年第34号），本文件引用同一份 ★ 结果，不再重复核验；未标注 ★ 的条文按二手来源处理并标级别。

## 要点1 · 流水数据质量与完整性基线

**字段**：无（口径基线，不直接判定）　**关联规则**：R117（中）、R118（低）

**口径**：

- `txn[]` 缺失或为空 → 输出空 findings + `coverage: partial`，**不臆测**（契约 IF-1.4 / IF-5.5）。
- 单笔 `amt` 非数字 → 该笔跳过；`date` 缺失 → 该笔不参与月份聚合。
- `period` 缺省 → 取 `txn` 覆盖的全部月份；`period` 只截取统计范围，**不改变单笔数据**。

**为什么单列一条**：本维度所有判断都建立在"流水是真实、完整、可归户"的前提上。  
**只有部分月份的流水**（比如客户只挑了好看的几个月给）与**完整流水**是两回事——  
前者应标 `coverage: partial`，否则会把"选择性披露"误读成"经营良好"。  
这一条是后面所有要点（波动、断档、集中度）的**数据前提**，前提不成立时结论一律降级为"待核实"。

**易错点**：

- 把"流水里没有大额出账"读成"用途合规"。字段缺失 → `None`（规则跳过 + 标 partial）；  
  字段为 0 → 确实无出账。二者不能混。
- 把 `period` 之外的数据也算进来 → 断档、波动、集中度全部失真。

## 要点2 · 数据清洗：内部互转／冲正／退款剔除

**字段**：`type`（内部类型集合）　**关联规则**：无（口径基线，所有指标的前置）

**口径**：`analyze.py` 里 `INTERNAL_TYPES = {transfer_internal, reversal, interest, fee_refund}`。  
以下 `type` 的交易**不计入经营收入**，在聚合前直接剔除：

| `type`             | 含义         | 为什么剔除                       |
| ------------------ | ---------- | --------------------------- |
| `transfer_internal` | 本人账户间互转   | 自己转自己，不产生真实收入，会虚增流水量        |
| `reversal`         | 冲正／撤销     | 一笔交易当天做了又撤，不是真实资金流          |
| `interest`         | 利息／结息入账   | 非经营所得，会污染"月均经营收入"           |
| `fee_refund`       | 费用退款      | 退款不是收入                     |

**为什么必须清洗**：农户个人卡与经营卡不分账（见 `征信审查要点.md` 要点16.4），  
本人账户互转、退款、结息在流水里极其常见。不清洗，这些"虚假入账"会：
① 抬高月均收入（`inc_mean`），压低波动系数（`inc_cv`）——把波动风险**抹掉**；
② 抬高总入账，把交易对手集中度（`top1_share`）稀释——把集中风险**抹掉**。

**易错点**：只按"金额相同"识别冲正，漏掉"当天大额进出对敲"的过桥资金（那不属于 `reversal`，  
见要点8）。内部互转与过桥资金是两类现象，**清洗口径不同**，不能共用一套判定。

## 要点3 · 收入稳定性（变异系数 `inc_cv`）

**字段**：`inc_cv`　**关联规则**：R101（高）、R102（中）、R111（高）、R114（低，季节性）、R124（中）

**口径**：

```
inc_cv = 月入账标准差 / 月均入账
```

- 分子分母都用**剔除内部交易后**的月入账序列（要点2）。
- 统计期**完整月份序列**参与计算（含"整月无入账"的月份——那正是波动最大的来源）。
- 月数 < 2 或月均入账 ≤ 0 → `inc_cv = None`（**不是 0**，见易错点）。

**分档与依据**：

| 条件                                          | 等级 | 规则   | 依据                      | 级别       |
| ------------------------------------------- | -- | ---- | ----------------------- | -------- |
| `inc_cv > 0.5 && seasonal_flag == 0`        | 中  | R102 | 波动大，还款来源不稳定（季节性农业除外）    | `[机构内控]` |
| `inc_cv > 0.5 && gap_cnt >= 3 && seasonal_flag == 0` | 高 | R101 | 波动叠加断档，双重恶化              | `[机构内控]` |
| `inc_cv > 0.7 && top1_share > 0.7 && seasonal_flag == 0` | 高 | R111 | 波动大且收入高度依赖单一对手           | `[机构内控]` |
| `inc_cv > 0.5 && seasonal_flag == 1`        | 低  | R114 | 季节性收入波动，属正常现象            | `[机构内控]` |
| `recent_in_ratio < 0.5 && seasonal_flag == 0` | 中  | R124 | 近期收入锐减，经营可能恶化            | `[机构内控]` |
| 环节差异                                        | —  | `thresholds` | 贷前/贷中 0.5 从严，贷后 0.7 放宽    | `[机构内控]` |

**为什么用变异系数（CV）而不是标准差**：标准差有量纲，10 万月收入波动 2 万 vs 2 千月收入波动 2 千，  
标准差看是"后者更稳"，但前者 CV=0.2、后者 CV=1.0——**相对波动**才是风险。  
农户收入量级差几个数量级，只有 CV 能跨客户可比。

**阈值从哪来（必须如实说明）**：**0.5 这条线没有任何监管出处。**  
50号文§19 ★ 只要求"建立合理的**收入偿债比例控制机制**"，不给"波动系数 ≤ X"。  
0.5 是**机构内控参数**（变异系数 0.5 约等于"月收入围绕均值上下摆 50%"，已属经营不稳定）。  
评审追问的答复口径："依据 50号文§19 的收入偿债控制机制要求，由机构内控设定的阈值"。

**易错点**：

- **`inc_cv = 0` 与 `inc_cv = None` 是两个世界**：无入账时 CV 无定义，必须 `None`，  
  填 0 会让 `inc_cv > 0.5` 永远不命中 → **波动风险静默消失**。
- 只取"有交易的月份"算 CV → 把断档月排除在波动之外，系统性低估。见要点4。

## 要点4 · 经营连续性（断档 `gap_cnt`）

**字段**：`gap_cnt`　**关联规则**：R103（中）、R101（高，与 `inc_cv` 组合）、R113（低，季节性）

**口径**：`gap_cnt` = **连续无入账 ≥ 1 个自然月**的"段数"（不是"空月总数"）。

- 统计期按 `period` 的**完整月份序列**展开，包含"整月无任何交易"的月份。
- 一段连续的空月算 1 段；两段空月之间只要有 1 个月有入账，就分开计 2 段。

**分档与依据**：

| 条件                                       | 等级 | 规则   | 依据             | 级别       |
| ---------------------------------------- | -- | ---- | -------------- | -------- |
| `gap_cnt >= 3 && seasonal_flag == 0`     | 中  | R103 | 经营疑似中断（季节性农业除外） | `[机构内控]` |
| `gap_cnt >= 3 && seasonal_flag == 1`     | 低  | R113 | 季节性停收，属正常现象      | `[机构内控]` |
| `inc_cv > 0.5 && gap_cnt >= 3 && seasonal_flag == 0` | 高 | R101 | 波动+断档双重恶化       | `[机构内控]` |

**⚠️ 季节性：这是本要点最需要防的误报（也是 `分工.md` 点名的第一缺口）**：

种粮农户**秋收后才有收入**，春、夏流水少甚至没有是**正常现象**，不是"经营中断"。  
50号文§17 ★ 明确"根据贷款项目**生产周期、销售周期**…合理确定贷款期限"——  
**监管承认农业收入的周期性**。因此：

- 纯 `gap_cnt >= 3` 只给"中"（R103），**绝不单凭断档判"高"**；
- 只有断档**叠加**波动（R101）才升"高"；
- **季节性识别是任务2 的待补项**：加 `industry`（经营品类）字段后，季节性农业的断档应**豁免**或降级，  
  把"真断档"和"季节性停收"分开。目前 `dict.yaml` 尚无 `industry` 短码，属已知缺口。

**为什么断档看"段数"不看"空月总数"**：连续 3 个月空 vs 每隔一个月空一个月，  
前者是"经营中断"，后者更可能是"周期性回款"（也即季节性）。段数能区分这两种形态。

**易错点**：只统计"有交易的月份"→ 断档永远算不出来（漏报）。  
`analyze.py` 的 `_month_range` 已按 `period` 展开完整月份，改口径时勿回退。

## 要点5 · 进出比（`in_out_ratio`）

**字段**：`in_out_ratio`　**关联规则**：R107（中）

**口径**：

```
in_out_ratio = 统计期总入账 / 统计期总出账
```

- 入账、出账均**剔除内部交易**（要点2）。
- **总出账为 0 时 → `None`**，不是 0（见易错点）。

**分档与依据**：

| 条件                 | 等级 | 规则   | 依据        | 级别       |
| ------------------ | -- | ---- | --------- | -------- |
| `in_out_ratio < 0.9` | 中  | R107 | 资金净流出，经营"吃老本" | `[机构内控]` |

**阈值从哪来**：0.9 是**机构内控参数**。监管只要求"了解收支情况"（50号文§23(二) ★  
"借款户**收入支出**与资产、负债等情况"），不给"进出比 ≥ X"。  
0.9 的含义是"出账比入账多 10% 以上，经营现金流持续失血"。

**易错点**：

- **总出账为 0 时填 `0` 会中招**：`0 < 0.9` 成立 → 一个只有入账、从不出账的客户被误报"资金净流出"。  
  这正是 `交付说明.md` §6 踩过的坑，`analyze.py` 已把此情形置 `None`。
- 入账为 0（无收入）时 `in_out_ratio = 0`，也会命中 R107——但此时更该先看要点1（数据不完整），  
  而不是报"净流出"。

## 要点6 · 最低余额／透支（`bal_min`）

**字段**：`bal_min`　**关联规则**：R108（高）

**口径**：`bal_min` = 统计期内**日终余额**的最小值。  
按交易时间顺序累加 `amt`，取余额曲线的最低点。

**分档与依据**：

| 条件           | 等级 | 规则   | 依据                     | 级别       |
| ------------ | -- | ---- | ---------------------- | -------- |
| `bal_min <= 0` | 高  | R108 | 账户曾透支，资金链脆弱            | `[机构内控]` |

**为什么透支直接判"高"**：正常经营账户很少触及 0 余额，更别说透支。  
透支说明账户处于"拆东墙补西墙"状态，或经营现金流长期入不敷出。  
与要点5（净流出）相比，透支是**更强的流动性信号**（已经动用了信用额度）。

**易错点**：

- **余额初值必须为空，不能以 0 起算**：若 `bal = 0.0` 起步，则任何账户 `bal_min ≤ 0` 恒成立，  
  R108 会对**每一个客户**误报透支。`analyze.py` 已用 `bal_min = None` 初值规避。
- 无交易时 `bal_min` 保持 `None`（无法计算），**不填 0**——否则又误报 R108。

## 要点7 · 交易对手集中度（`top1_share`）

**字段**：`top1_share`（入账侧）、`top1_debit_share`（出账侧）　  
**关联规则**：R104（中）、R105（高）、R111（高，与 `inc_cv` 组合）、R115（低，出账侧）、R116（中，出账侧）

**口径**：

```
top1_share = 单一交易对手入账额 / 总入账额
```

- 只算**入账**（收入侧），对手按 `counterparty` 字段聚合；`counterparty` 缺失归入"未知"。
- 同一名称的不同写法（"某合作社" vs "某合作社财务部"）**不自动归一**——这是已知局限（见易错点）。

**分档与依据**：

| 条件                          | 等级 | 规则   | 依据            | 级别       |
| --------------------------- | -- | ---- | ------------- | -------- |
| `0.6 < top1_share <= 0.85`  | 中  | R104 | 收入依赖单一对手       | `[机构内控]` |
| `top1_share > 0.85`         | 高  | R105 | 单一对手高度依赖，对方一倒即断 | `[机构内控]` |
| `inc_cv > 0.7 && top1_share > 0.7` | 高 | R111 | 波动+集中双重恶化      | `[机构内控]` |

**阈值从哪来**：0.6 / 0.85 是**机构内控参数**。监管只要求贷前调查"借款户收入支出与资产、负债等情况"  
（50号文§23(二) ★），不给"单一对手占比 ≤ X"。  
0.85 的含义是"85% 收入来自同一个买家，该买家停止采购即断收入"。

**为什么这是农户贷款的高危信号**：种植/养殖户的销售渠道往往单一（一个收购商、一家合作社），  
集中度天然偏高，**但"偏高"到什么程度才叫风险，没有监管数字**。  
所以分档要**给足区间**（0.6–0.85 中、>0.85 高），避免把"正常的单一渠道"一棒子打死。

**易错点**：

- 对手名称不归一 → 同一个对手被拆成多个，`top1_share` 被系统性**低估**（漏报）。  
  任务3 待补：按名称/账号归一化的模糊匹配。
- 只算入账、不算出账：出账侧集中（只向一家供应商采购）是**另一个**风险（上下游集中度），  
  当前短码未覆盖，属任务2 待补项。

## 要点8 · 大额交易与单笔异常

**字段**：`large_in_share` / `p2p_cnt` / `round_trip_cnt`　  
**关联规则**：R119（中）、R120（高）、R121（高）、R123（中）

**口径**：`LARGE_DEBIT = 5000 元`。出账 ≥ 5000 元计为"大额出账"，参与用途偏离判定（要点11）。  
入账侧的大额单笔暂未单独建模。

**为什么单列一条（这是任务2 的"过桥资金／关联互转"规则的落脚点）**：

`分工.md` 点名的两类缺口，都建立在大额交易的时序特征上：

1. **过桥资金**：放款前**集中大额进账**、放款后**立刻大额转出**——用别人的钱垫出"漂亮流水"，  
   典型的骗贷手法。识别要靠"大额进账时间窗 vs 放款时间窗"的时序比对。
2. **关联账户互转**：自己（或亲属）账户间互转**刷流水**，制造虚假交易量。  
   与要点2 的 `transfer_internal` 不同——那是有 `type` 标注的显式互转，  
   这里是**跨账户、无标注**的对敲，识别要靠"对手方为亲属/本人他户 + 金额对等 + 短时间窗"。

**当前状态**：这两类规则**尚未实现**（无短码、无规则），属 `分工.md` 任务2 的明确待办。  
本要点先占住"大额交易"这个口径位置，避免后续规则悬空引用。

**易错点**：把大额判定阈值当监管数字——5000 元是**机构内控参数**，随农户贷款单笔金额量级设定。

## 要点9 · 非经营时段交易（`night_txn_share`）

**字段**：`night_txn_share`　**关联规则**：R109（低）

**口径**：`night_txn_share` = 22:00–06:00 交易的**笔数**占比（不是金额占比）。  
交易时间从 `date` 字段解析（`T` 或空格后的 `HH:`）。

**分档与依据**：

| 条件                    | 等级 | 规则   | 依据           | 级别       |
| --------------------- | -- | ---- | ------------ | -------- |
| `night_txn_share > 0.3` | 低  | R109 | 交易时段异常，提示性关注 | `[机构内控]` |

**为什么只给"低"**：农户经营（早市、夜市、赶集）本就可能延伸到晚间，且网银/手机银行转账  
在任何时段都可能发生。夜间交易**不能单独证明风险**，只能作为"提示性关注"线索。  
判高会造成大量误报。

**易错点**：`date` 缺时分秒时，`_hour()` 兜底为 12（中午）——不算夜间，属保守处理，不报风险。

## 要点10 · 现金收入占比（`cash_inc_ratio`）

**字段**：`cash_inc_ratio`、`large_cash_out`　**关联规则**：R110（中）、R122（中）

**口径**：`cash_inc_ratio` = 现金渠道入账 / 总入账。  
现金渠道集合 `CASH_CHANNELS = {cash, counter_cash, atm_cash}`。

**分档与依据**：

| 条件                    | 等级 | 规则   | 依据               | 级别       |
| --------------------- | -- | ---- | ---------------- | -------- |
| `cash_inc_ratio > 0.7`  | 中  | R110 | 收入以现金为主，难验证真实性 | `[机构内控]` |

**为什么现金占比高是风险**：现金收入**无法追溯真实来源**，也无法与经营流水交叉验证。  
农户确有大量现金交易（赶集、地头交易），所以**只给"中"**，判高会误伤正常农户。  
50号文§36 ★ 从**发放端**反证了现金的口径问题——"自主支付必须转入**指定的借款人结算账户**，  
**严禁以现金方式发放贷款**"。收入端虽无同样明文，但"收入可验证"是贷前调查的内在要求。

**易错点**：现金占比高**本身不是问题**，问题在于"高现金占比 + 无其他佐证"时收入无法核验。  
R110 的处置建议是"核实现金收入来源"，不是直接降级。

## 要点11 · 资金用途偏离（`loan_use_dev`）

**字段**：`loan_use_dev`　**关联规则**：R106（高）、R112（中）

**口径**：

```
loan_use_dev = 与申报用途无关的大额出账额 / 大额出账总额（出账 >= 5000 元）
```

- 大额出账判定见要点8（`LARGE_DEBIT = 5000`）。
- "相关"的判定：出账的 `counterparty + desc` 命中**申报用途词**（`purpose` 拆分）或  
  **通用农业词**（`AGRI_WORDS`，含农资/化肥/种子/农药/农机/饲料/兽药/地租/承包/大棚/苗木/牲畜/仔猪/鱼苗/柴油/水电）。
- 命中任一即计"相关"，否则计"偏离"。

**分档与依据**：

| 条件                              | 等级 | 规则   | 依据                         | 级别         |
| ------------------------------- | -- | ---- | -------------------------- | ---------- |
| `0.1 < loan_use_dev <= 0.3`     | 中  | R112 | 用途轻微偏离，补充用途说明               | `[机构内控]`     |
| `loan_use_dev > 0.3`            | 高  | R106 | 大额出账明显偏离申报用途，须核实真实去向        | `[法定]`（挂靠） |

**R106 的监管挂靠（这条是流水维度依据最硬的一条）**：

| 依据             | 原文要点                                     | 级别       |
| -------------- | ---------------------------------------- | -------- |
| 50号文§14 ★      | 贷款用途须**合法、合规**，符合国家产业政策                   | `[法定]`   |
| 50号文§36 ★      | 自主支付须转入**指定的借款人结算账户**，**严禁现金发放**，确保资金发放给真实借款人 | `[法定]`   |
| 个人贷款办法§10 ★   | "结合借款人已有债务情况，审慎评估借款人还款能力"；贷款**用途明确、合法** | `[法定]`   |

> ⚠️ 注意：这三条是"用途合法 + 资金发放合规"的**机制要求**，**没有**"用途偏离度 > 30% 即违规"的数字。  
> `0.3` 这条线是**机构内控参数**，挂靠监管的是"用途须合法、资金须可追踪"这个**定性要求**。

**为什么用"大额出账"而非"全部出账"**：小额日常消费（超市、日用）天然与经营用途无关，  
用全部出账算会把正常生活开支算成"用途偏离"。只看大额出账，才是"钱的大头花到哪去了"。

**易错点**：

- `AGRI_WORDS` 是**通用农业词兜底**，不能识别"购置农机"这种具体用途——  
  具体用途靠 `purpose` 拆分词命中。`purpose` 缺失 → 只有 `AGRI_WORDS` 兜底 →  
  偏离度会**偏高**（误报），此时应标 `coverage: partial` 而非直接报高。
- "无大额出账"时 `loan_use_dev = 0`（不是 `None`）——确实没有偏离，不是数据缺失。
