# 贷后预警信号 · sk_ew

> 配套：`references/rules.closure.md`（本包规则）｜`skills/sk_cash/references/流水分析要点.md`（贷后流水趋势）
> 本文件是 `sk_ew` 的**信号字典**：定义每个信号的阈值、升级/解除条件与处置动作。
> **规则里 `basis` 列的「贷后预警信号N」指的就是本文件的编号**——编号即契约，不得重排、不得复用。
> 依据现行行内制度：**《中国农业银行农户贷款贷后管理办法》农银规章〔2020〕110号**（2020-07-27 施行）。

## 0. 怎么用这份信号表

```
① 逐时点求值   →  对 monitor_ts[] 的每个时点，按「触发阈值」列判定命中哪些信号
② 时序比对     →  套用 §3 的升级/解除/跨档规则（单点异常不升级）
③ 定级处置     →  按「初判」列取等级，按 §4 动作库给处置建议
④ 输出 alerts  →  只报**最新时点**仍成立的信号，附升级轨迹与解除状态
```

**三条纪律**

1. **单点异常不升级**。信号必须在**连续 ≥2 个监测时点**出现才升一档——一次回访联系不上、一个月余额低，都是正常波动。
2. **解除不自动生效**。「拟解除」只是提示，最终解除要人工确认；系统擅自解除会掩盖真实风险。
3. **算不出来填 `None`**（契约 IF-1.4）。`bal_drop` 无上期余额时置 `None`，**不可填 0**——`0` 不触发任何阈值看似安全，但一旦表达式写成 `<0.5` 就会误报，是同一个坑的变体。

**信号9 与 20–23 的关系**：`信号9` 是**伞形信号**（担保整体弱化），`信号20`–`信号23` 是它的四个子情形。
规则按**子情形**分别定级、分别给处置动作；`信号9` 只在无法归因到具体子情形时兜底使用。**不要为同一事实同时报 9 和 20**。

**信号34–41 的来源**：这 8 个信号不是凑数的，是**行内制度明文列出的贷后检查与风险问题**，
§6 有逐条对照。`信号34`–`信号36` 是 2020贷后办法第三十一条(一) 点名的三类违规用信，
`信号37` 来自第三十二条（洗钱风险），`信号39`/`信号40` 来自第三十一条(六)(七)。

**信号42–45 的来源**：来自**另一套明文的风险清单**——《中国农业银行农户贷款风险线索
核查处置操作规程（试行）》**农银规章〔2020〕70号 第八条**（2020贷后办法第十六条点名该规程）。
它把风险线索分**重大类/关注类/一般类**三级，并逐类列举了具体线索。这四条是与
`信号1`–`信号41` **互补的视角**：前者是客户经理/系统对**单笔贷款**的观察，
后者是**系统在存量里跑出来的归集性线索**（多户流同一账户、多户同一账户还款、批量现金还款），
以及**内部作业风险**（员工与客户资金往来）。`信号42`/`信号45` 是关注类/重大类中
最严重的两条，故定「高」。

## 2. 等级标尺与处置倾向

沿用契约 IF-1.1 的三档标尺（`sk_ew` 不自造等级）：

| 等级 | 本 skill 中的含义 | 处置倾向 |
|---|---|---|
| `高` | 已发生或高度可能发生违约/资产损失 | 提前收回并终止用信、提前收贷、资产保全、诉讼 |
| `中` | 还款能力或还款意愿出现实质削弱 | 降额追加担保、上门催收、增频检查、限期补办 |
| `低` | 值得记录的苗头，不阻断 | 提示风险、记录备查、增频观察 |

> **本 skill 的等级只反映"这笔贷款在时间轴上的恶化程度"**。若需与征信、材料交叉（如"逾期且新增多头"），
> 输出两个维度的事实，等级由 `sk_rules` 合成（契约 D2）。

## 3. 时序判定（本 skill 区别于快照判定的核心）

### 3.1 信号升级

```
信号在连续 ≥2 个监测时点出现          →  升级一档（低→中→高），封顶「高」
信号在连续 ≥3 个监测时点出现          →  进入 §4 的「强制处置」通道
信号在连续 ≥3 个时点未消失且等级已为高 →  升级为「提前收回」建议
```

### 3.2 信号解除

```
信号在最近 2 个监测时点均未出现  →  标记「拟解除」（不自动解除）
信号在最近 3 个监测时点均未出现  →  标记「建议解除」，仍待人工确认
逾期类信号解除必须同时满足：overdue_days=0 且 连续 2 时点
```

### 3.3 逾期档位与催收阶段（**两个不同的尺子，别混用**）

**尺子一：风险分类档位**（监管口径，用于定级）。逾期档位与风险分类联动，**跨档即升级，不看连续时点数**。

**「跨档」的准确定义（写脚本时定死的，别再解释成别的）**：
档位**升到「次级」及以上**才算跨档，即越过 31 天或 90 天这两条线。

> 为什么"正常→关注"不算跨档：那只是刚出现逾期。任何一笔新的小额逾期都会落到关注档，
> 若算作跨档就直接判高——这是典型的误报。刚逾期由 `信号1` 判「中」，只有恶化到次级以上才强制升级。

| 档位 | 天数 | 初判 | 风险分类参照 |
|---|---|---|---|
| 正常 | 0 | —— | 正常 |
| 关注 | 1–30 | 中 | 至少关注类 |
| 次级 | 31–90 | 高 | 逾期超 90 天至少次级 |
| 可疑 | 91–270 | 高 | 逾期超 270 天至少可疑 |
| 损失 | 271+ | 高 | 逾期超 360 天应归损失 |

> 逾期超过 **270 天**、**360 天**分别触发「至少可疑」「应为损失」的强制档位，
> 这两档的处置动作固定为「启动资产保全 / 依法追偿，不得以展期、重组名义延缓降级」。

**尺子二：行内催收阶段**（操作口径，用于定处置动作）。依据 **2020贷后办法第四十一条**：

```
逾期后              总行在 5 个工作日内集中远程催收（短信提醒、电话外呼）
逾期后              经营行对借款人及担保人电话或上门催收
逾期 15 天以上      应上门催收                                  ← 行内新口径
逾期 91 天以上或已形成不良  司法催收；失联或资产转移可不受时限
上门催收            应取得《催收回执》（第四十二条）
```

> ⚠ **一处已修正的口径**：本文件旧版写「现场催收：逾期 31–90 天」，
> 那是**已废止的**农银规章〔2014〕93号第三十九条的旧口径。现行是**逾期 15 天以上应上门**。
> 别把 15 天这条线与 §3.3 的 31 天档位线混为一谈——前者管"谁去催"，后者管"判什么等级"。

### 3.4 展期与重组的边界

因**自然灾害、农产品价格波动、疫情等客观原因**导致无法正常还款的，可申请展期
（2020办法第十一条、2020贷后办法第三十八条）：

- 展期须经申请同意，**已展期贷款不得再次展期**；
- **展期贷款最高列入关注类管理**——不得因展期而维持正常类；
- 协议重组的前提是：利息还清、本金部分偿还、**原有担保措施不弱化**（2020办法第四十五条）。
- 上述三条是硬边界，**展期建议不得绕过**。

## 4. 处置动作库

处置建议必须是**动词短语、≤16 字**（契约 IF-4.1 的 `advice` 列）。按等级取用：

```
等级|动作（择一）|触发场景
高|提前收回并终止用信|冒顶名、多人承贷一人使用、个人承贷公司使用（第三十一条）
高|宣布提前到期|资金流入禁止领域
高|启动资产保全|涉诉、账户冻结、损失类逾期
高|移交内部合规核查|员工与客户资金往来等**重大类**风险线索（风险线索规程第八条(一)）
高|依法追偿|逾期 91 天以上或已形成不良（第四十一条(三)）
高|压降额度并追加担保|押品贬值、保证人代偿能力下降
中|上门催收并评估处置|逾期 15 天以上（第四十一条(二)）
中|降低额度并追加担保|生产经营不善、还款意愿减弱（第三十条）
中|限期补办手续|检查未达频次、抵押登记失效、首贷检查超期
中|增频检查并跟踪|价格冲击、上下游恶化、用工收缩
中|提示并核实情况|失联、拒绝检查、家庭变故
低|继续观察记录备查|余额下降等苗头信号
```

**动作来源就是行内的风险问题清单**——`2020贷后办法` 把风险问题分成两档，处置动作与之严格对应：

```
第三十条  一般风险问题（6 项）→ 降低额度 / 要求补充担保物或增加保证人 / 提前部分或全部收回贷款
第三十一条 严重风险问题（9 项）→ 提前收回贷款 / 终止用信
第三十三条 处理时限             → 整改应在发现问题后 30 个工作日内完成
```

**处置优先级排序**：高等级信号按「资产保全 > 提前收贷 > 追加担保 > 增频检查」顺序输出；
同等级多条时，**处置动作最重的排最前**（主智能体按序取第一条作为建议）。

**一条硬纪律（风险线索规程第十六条）**：

> 通过**提前收回**问题贷款处置风险的，**除非违规行为得到纠正且风险完全可控，
> 严禁再次向该借款人发放农户贷款（包括可循环方式）**。

这是**禁止性规定**，不是"建议"。所以凡因本 skill 的信号走到「提前收回」的案子，
输出里应保留该笔的处置结论——**它同时是一条再贷的闸门**，不能因为预警解除了就恢复放款资格。
（`ew.py` 的「拟解除」只是提示，**不自动解除**，这个设计在这里又多了一层理由。）

### 5.1 登记状态与实现方式（2026-10-09）

上表 32 个短码**已按 `sk_cred` 扩容时的先例登记进 `rules/dict.yaml` 的 ew 段**
（注释里标明"评审通过前不得在其他 skill 的 cond 中引用"，契约 IF-4.2）。
其中 7 个是 `ew.py trend` 算出的派生量，不必由上游逐时点提供：

```
短码|来源|含义
signal_streak|ew.py evaluate 按 basis 注入|该规则「所属信号」已连续出现的时点数
overdue_band_crossed|ew.py trend|逾期档位升到「次级」及以上（越过 31 天线）
n_ts|ew.py trend|监测时点总数
ew_max_streak|ew.py trend|仍成立的信号中最大的连续时点数
ew_upgrade_cnt|ew.py trend|状态为「升级」的信号个数
ew_force_cnt|ew.py trend|连续 ≥3 时点仍成立的信号个数（§3.1 强制处置通道）
ew_release_cnt|ew.py trend|拟解除的信号个数（§3.2）
```

> **`signal_streak` 是「按规则注入」的，不是全局量**：`ew.py evaluate` 靠规则 `basis` 列的
> 「贷后预警信号N」认出这条规则属于哪个信号，再把**那个信号**的连续时点数放进它的求值作用域。
> 所以规则 `overdue_days>30 && signal_streak>=3` 说的是"逾期这个信号连续 3 期"，
> 而不是"某个不知名信号连续 3 期"。**写规则时 `basis` 必须写对信号号**，否则拿到的是别人的 streak。
>
> 规则不由信号驱动时（如聚合规则）拿不到 `signal_streak` → 引用它的规则被跳过，不会误报。

### 5.2 输入形状兼容（数组与单对象都认）

契约 IF-3 声明的槽是 `monitor_ts[]`（**时点数组**），但上游给的可能是
`monitor{}`（**单对象快照**）——题目里现在就是这个形状。`ew.py` 两种都认：

```
monitor_ts[] / monitor[]  → 时点数组，正常跑
monitor{} 单对象          → 当作 1 个时点跑，并在 `derived.coverage` 标 "partial"
```

**单对象必须标 `partial`，不能装作能判时序**：本 skill 的核心是
「连续 ≥2 个时点才升级」「最近 2 个时点消失才拟解除」「逾期跨档」——
这些在 1 个时点上**原理上不成立**。所以脚本会明说"时序能力不可用"，
而不是把快照结论伪装成动态预警。**整条输出里凡有时序结论的，此时都不可信。**

字段名/取值也做适配（只翻译形状，**不改口径**）：

```
上游可能给的                → 翻译成
monitor_date / 业务日期     → date
biz_status: "正常经营" 等   → biz_abnormal: 0/1（非"正常经营"置 1）
contact:    "可联系" 等     → contact_fail:  0/1（非"可联系"置 1）
bal_drop（直给）            → **不采信**，并说明原因
```

> `bal_drop` 契约口径是 `(上期余额-本期余额)/上期余额`。输入再直给一个数就有了
> 两套口径，迟早对不上——所以宁可不判这个信号（跳过优于臆测），也不采信输入值。
>
> 这些翻译**只是形状兼容**：连续时点数、跨档、余额下降率的口径一律不变。
