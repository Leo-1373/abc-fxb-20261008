# 必备材料清单 · sk_doc

> 配套：`references/rules.closure.md`（本包规则）｜`skills/sk_cash/references/流水分析要点.md`（收入类材料的真伪靠流水交叉验证）
> 本文件是 `sk_doc` 的**判定基准**：先按「情形」取清单，再逐项比对，最后把缺件/矛盾折算成 `doc` 维度短码。
> 表里 `type` 列是 `doc[].type` 的规范取值，**也是 `scripts/check.py` 的输入格式**——改表即改脚本行为，但不能改 `type` 代码（脚本按代码点名匹配）。

## 0. 怎么用这份清单

```
① 判情形   →  从 applicant 的 purpose / business 推断属于哪些情形（种植、养殖、水产、农机、联保、个体工商户……）
② 取清单   →  情形必备项 = 「必」+ 命中的「条件」项；其余为「选」
③ 逐项比对 →  缺件数 → doc_miss_cnt ｜ 过期数 → doc_expired_cnt ｜ 矛盾数 → doc_inconsist_cnt
④ 判红线   →  缺失项若在「§6 红线材料」内，redline_hit=1，交 sk_rules 的 X007 定准入后果
```

**三条纪律**

1. **缺失 ≠ 风险**。`doc` 只报"少了哪几项"这个事实，缺件的准入后果由 `sk_rules` 判（本 skill 边界）。
2. **条件项未命中不算缺件**。养鸡户没有《水域滩涂养殖证》是正常的，不计入 `doc_miss_cnt`——判错情形会直接制造误报。
3. **算不出来填 `None`，不填 `0`**（契约 IF-1.4）。`doc_miss_cnt` 无法计算时置 `None` 并标 `coverage: partial`，不可默认 0。

**两类表，别混**

```
§1/§2/§3 主表（8 列）   客户提交与签署的要件 → **参与缺件计数**
§1.1/§2.1/§3.1 附表      经办留档表单（记录类）→ **不参与缺件计数**，只做合规检查
```

附表用**不同的表头**，`check.py` 按表头精确匹配，天然跳过——**附表不是漏解析，是设计如此**。
理由：「面谈记录没做」和「身份证没交」不是同一件事。前者是经办合规问题，后者直接卡准入；
若混在同一张表里计数，任何只提交客户材料的输入都会凭空多出 3 项缺件、跨过 `doc_miss_cnt>=3` 直接判高。

**依据列的两种取值**（口径见 §9）：

- 行内制度条款号 → 四份行内文件里写明的，可直接引用、可直接定级；
- **`【待核实】`** → 四份行内文件**没有覆盖**这条材料。这类条目一律 **`必需=选`、`红线=0`**——
  依据都没拿到，就不许它驱动缺件数和准入红线。等补下对应文件后回填，再决定是否升为要件。

## 5. 核验要点详解

### 5.1 时效性（→ `doc_expired_cnt`）

```
过期 ⇔ expire_date 非空 且 expire_date < 受理日
```

- `expire_date` 为空**不等于过期**——多数材料（合同、权证、申请表）本就没有有效期。空值置 `None` 并跳过，**不可当作已过期**。
- **各证照的有效期以其自身签发规则为准**（身份证、营业执照、动物防疫条件合格证、评估报告各不相同）。四份行内文件**均未规定**具体年限，因此本清单不给推定值——按签发日加行业有效期推定，推定值须在 `ev` 中标明是推定。
- 临期预警（距到期 ≤30 天）不属于"过期"，只提示。

**行内制度里有明文期限的口径**（这些不是推定，是硬依据）：

```

现场必查·信用30-100万     每年至少 1 次                  2020贷后办法第二十一条(二)1
现场必查·非信用50-200万   每年至少 1 次                  2020贷后办法第二十一条(二)1
现场必查·信用100万以上    每年至少 2 次                  2020贷后办法第二十一条(二)2
现场必查·非信用200万以上  每年至少 2 次                  2020贷后办法第二十一条(二)2
```

### 5.2 一致性（→ `doc_inconsist_cnt`）

跨材料比对**同一个事实**，每有一处对不上计 1：

| 比对项 | 比对对象 | 典型矛盾 |
|---|---|---|
| 姓名 | `holder` × 申请表 × 户口簿 × 合同签字 | 音近字不同（"张桂lan" vs "张桂岚"） |
| 证件号 | 身份证 × 合同 × 担保人资料 | 位数或末位不符 |
| 面积 | 土地权证 × 申报面积 × 项目计划书 | 权证 12 亩、申报 15 亩 |
| 金额 | 购销合同 × 申请额度 × 评估报告 | 合同 8 万、申请 10 万 |
| 日期 | 合同签订日 × 放款日 × 流水时间 | 合同早于调查、放款早于签约 |
| 签章 | 应签章处逐个数 | 缺担保人签字、缺公章 |

> **姓名、证件号只比"申请人本人署名"的材料**（`ID_CARD` / `LOAN_APPLY` / `LOAN_CONTRACT` / `ACCOUNT_PROOF`）。
> 配偶身份证、保证人身份证上的姓名**本来就不等于申请人**，逢件比对会把每个已婚申请人都判成矛盾（误报）。

### 5.3 权属与签章

- `land_right_match` = 权证记载面积与申报面积的偏差是否在 ±5% 内（超出判 0）。
- `sign_complete` = 所有应签章处（申请表、合同、担保合同、承诺书、联保协议）是否齐全；**代签、打印体签名、无骑缝章**均判不完整。
- `id_valid` = 身份证在有效期内 **且** 与申请人一致。两者缺一即 0。
- **行内明文要求签字的表单**（缺失即不完整）：面谈记录、贷后现场检查表（须借款人或家庭成员签字）、催收回执。
  脚本当前机器校验的签章项是 `LOAN_APPLY / LOAN_CONTRACT / GUARANTEE_CONTRACT / GUARANTOR_CONSENT / JOINT_GUARANTEE_PACT / COOWNER_CONSENT`——新增三张表单**尚未纳入脚本**，模型判到时按本条手工计。

## 8. 与脚本的衔接

`doc[].type` 取本文件表中的 `type` 列（**含 §1.1/§2.1/§3.1 附表**——它们不参与缺件计数，
但仍是合法 type，脚本按全部表的 type 判"清单外材料"）。若上游给的 `type` 不在表内：

- **不要当作缺失**（可能是清单未覆盖的新材料）→ 计入 `doc_unknown_type_cnt`（R029，低）；
- 在输出的 `facts@doc` 的 `unknown_types` 里列出，供 P3 迭代清单。

`doc[]` 每项的 `fields{}` 用于一致性比对，约定字段名与 §5.2 的比对项一致：

```
{type, no, issue_date, expire_date, holder, fields{name, id_no, area, amount, sign_date, seal_count, ...}}
```

### 8.1 脚本产出的短码（`scripts/check.py check`）

对齐 §7 的靶子，脚本产出下列指标；**算不出来一律 `None`**（契约 IF-1.4），
`None` 的规则会被 `evaluate` 跳过，不会误报：

```
指标|含义|算不出来的情形
doc_miss_cnt / doc_miss_redline_cnt|缺件总数 / 其中命中 §6 红线的件数|doc[] 为空
doc_miss_{identity,income,use,guarantee,biz,contract,postcheck,archive}_cnt|按类别拆的缺件数|同上
doc_expired_cnt / doc_expired_key_cnt / doc_expired_soon_cnt|过期总数 / 关键证照过期 / 临期(≤30天)|expire_date 为空或受理日缺失
doc_inconsist_cnt|矛盾总处数|——
doc_inconsist_{name,idno,area,amount,date}_cnt|按比对项拆的矛盾处数|同上
doc_sign_missing_cnt|已提交材料中签章不齐的项数|没有应签章材料被提交
doc_unknown_type_cnt|清单外材料的项数|清单解析不到 type 列
doc_land_area_dev|权证与申报面积的偏差比例|权证或申报面积缺值
id_valid / land_right_match / sign_complete|§5.3 的三项核验|相关材料没交
doc_interview_missing|贷前未交面谈记录|非贷前环节
doc_first_check_overdue_days|首次贷后检查超期天数|非贷后、缺放款日、或检查记录整份没交
doc_onsite_check_shortfall|现场检查欠做次数|非贷后、额度低于起档、或担保方式判不出
doc_entrust_amt_short|购销合同金额低于申请额度|无购销合同或金额/额度缺值
```

**三处口径要写清楚，免得被当成 bug：**

1. `doc_first_check_overdue_days` **只在拿到检查日时才判**。检查记录整份没交属于**缺件**
   （R017，7-12），不在这里重复报——同一事实报两次是误报的来源。
2. `doc_onsite_check_shortfall` **按「每年至少 N 次」直接比 N 次，不做年度折算**（简化口径）。
   额度低于起档（信用 30 万 / 非信用 50 万）的属"现场抽查"，按管理户数比例考核，
   没有固定次数 → 返回 `None`。分档见 §5.1，来自 2020贷后办法第二十一条(二)。
3. `doc_interview_missing` 报的是"**未留痕**"这个事实，不是"违规"的判定——
   第十八条允许"采用技术手段能够核实身份和生产经营真实性的，可通过非现场方式完成"。
   有豁免情形时由模型在输出里说明，脚本不下结论。
